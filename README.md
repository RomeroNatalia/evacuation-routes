# Evacuation Routes: Certified Optimality Gaps and Structural Bottleneck Analysis for Capacity-Aware Indoor Evacuation Routing

This repository models indoor building evacuation as a capacity-aware QUBO route-assignment problem and compares distance-only Dijkstra/A\*, greedy congestion-aware Dijkstra, classical simulated annealing (Neal), D-Wave Leap Hybrid, direct D-Wave QPU sampling, and an exact certified-optimal MILP baseline (Google OR-Tools CP-SAT) across 23 floorplans.

It began as Arielle Jenna Fishman's FAU Machine Perception and Cognitive Robotics Laboratory fellowship capstone (5 real floorplans, 390 benchmark runs). This fork extends that original work — co-authored by Arielle Jenna Fishman and Natalia Romero, Ph.D. — with a certified optimality baseline, formal significance testing, a root-cause investigation of solver difficulty, and an 18-floorplan controlled synthetic corpus. The full writeup is in [`paper/main.pdf`](paper/main.pdf) (LaTeX source: [`paper/main.tex`](paper/main.tex)), prepared for arXiv submission.

**Branches**: `main` has everything merged together (recommended). `expansion/milp-optimality-gaps` retains the expansion work as its own history, kept separately for reference.

## What's in the paper

- **Certified optimality gaps** (Section 6, 9.2): the QUBO's exactly-one constraint, once separated from its penalty-method encoding, makes the underlying problem a convex integer quadratic program — solvable exactly with CP-SAT in under two seconds per floorplan, no embedding or penalty tuning required. Measured against these certified optima rather than each other, Neal and Hybrid land 94–124% above true optimal on FP02 and FP03 — the two floorplans that also couldn't be embedded on the QPU — a gap invisible in a solver-vs-solver comparison alone.
- **Root-cause investigation** (Section 9.4–9.5): rules out insufficient compute budget directly (a 100× sweep-count increase on Neal does not close the gap), then quantifies structural bottlenecks in the raw navigation graphs three independent ways (capacity, traffic-concentration, and topological/bridge-based).
- **An 18-floorplan synthetic corpus** (Section 9.6): three independently-controlled corridor topologies (linear spine, branching tree, looped ring) × three sizes × two seeds, generated in the same schema as the real floorplans and validated through the same test suite. Statistically confirms — and corrects — the structural hypothesis: corridor diameter, not bridge/critical-bridge count (the initial working hypothesis), is the dominant predictor of solver difficulty, replicated under both Neal and Hybrid with Bonferroni-corrected Mann-Whitney testing.
- **Floorplan blueprints** (Appendix C): navigation-graph visualizations for all 23 floorplans (14 unique layouts — synthetic seeds share identical structure).

## Installation

Python 3.10 or newer is required.

```bash
python -m venv .venv
source .venv/bin/activate       # macOS/Linux
# .venv\Scripts\Activate.ps1  # Windows PowerShell
python -m pip install --upgrade pip
python -m pip install -e ".[dev]"
python -m pip install ortools scipy matplotlib  # needed for scripts/expansion/
```

Configure Leap only for Hybrid or direct-QPU jobs:

```bash
dwave setup --auth
```

**Never commit a D-Wave API token to any file.** Pass it as an environment variable only: `DWAVE_API_TOKEN=... python scripts/...`.

## Select a floorplan

Every active script accepts `--floorplan`. FP01 is the default; any of the 23 floorplan IDs above works.

```bash
python scripts/run_preprocessing_pipeline.py --floorplan FP01
python scripts/run_preprocessing_pipeline.py --floorplan SYN_LOO_20_S1
```

Process all included real datasets:

```bash
python scripts/run_all_preprocessing.py
```

## Solve the QUBO

```bash
python scripts/solve_qubo_neal.py --floorplan FP04
python scripts/solve_qubo_hybrid.py --floorplan FP04
python scripts/solve_qubo_qpu.py --floorplan FP04

# Certified-optimal baseline (this expansion, no D-Wave account needed):
python scripts/expansion/milp_optimality_gap.py FP04
```

Cloud solvers submit quota-limited jobs. Larger floorplans may not embed directly on the QPU; an embedding failure is a legitimate scaling result rather than a preprocessing error. The MILP baseline has no such limitation and solves every floorplan in this repo in under two seconds.

## Model scope

This is a static, capacity-aware route-assignment model. It does not simulate time-dependent queues, smoke spread, walking speed, panic, or individual occupant behavior. The optimized objective combines normalized route distance and normalized squared edge utilization; the exactly-one-route constraint is enforced as a penalty term for the heuristic/quantum solvers, and as a native linear constraint for the certified MILP baseline. See `paper/main.pdf` for the full formulation, all limitations, and future work.
